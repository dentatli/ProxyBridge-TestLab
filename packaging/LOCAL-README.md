# ProxyBridge TestLab — «На этом ПК»

1. Запустите `Start.cmd` и подтвердите запрос Windows на права администратора.
2. В разделе «Сборки» нажмите «Найти установленный ProxyBridge» и выберите найденный комплект. Для нестандартной установки можно указать папку вручную. Типы: «Driver WFP» и «WinDivert». Для WinDivert поддержка заявлена только для версии 4.3.0; поддержка остальных версий не заявлена. Номер версии определяется отдельно от типа; старые сохранённые выборы сохраняют свои идентификаторы.
3. Откройте «Тестирование» → «На этом ПК». Выберите одну из десяти проверок, полноту, длительность и нагрузку. «Этапы и точный выбор» раскрывает внутренние сценарии.
4. Откройте «Запуск». Остановка выполняется кнопкой в приложении; дождитесь результата очистки. Общий статус и подробности этапов доступны в «Результатах».

Для первого короткого запуска подходит TCP → Базовая → Быстро → Низкая: три этапа, оценка около 1,3 минуты. Это оценка времени с подготовкой, а не гарантированный предел. Длительность выбранного набора видна перед запуском.

Транспорт TCP/UDP, приёмник и SOCKS5-реле работают на C#. Проверенные прикладные библиотеки SSH/SFTP, HTTP/2, QUIC и других протоколов сохранены. В комплекте есть .NET и Python 3.11 с зависимостями. Отдельная установка Python, Ubuntu или настройка SSH для локального режима не нужна. ProxyBridge устанавливается пользователем отдельно. TestLab не устанавливает продуктовый драйвер и не меняет системные параметры подписи или доверия.

Проверка файлов установки не означает подтверждения совместимости или успешного прохождения сетевых сценариев. Ошибки продукта, маршрута и очистки сохраняются как ошибки. Неподтверждённые измерения не становятся PASS.

Сохранённые наборы импортируются и экспортируются в прежнем формате с атомарными ID. Если наборы были сохранены в браузере на другом порту, экспортируйте их там и импортируйте в этом приложении. История попыток хранится в `%LOCALAPPDATA%\ProxyBridge-TestLab\traffic-lab`; настройки выбора файлов защищены Windows DPAPI.

`packaging\Repair-ProxyBridge-TestLab.ps1` проверяет комплект по SHA256SUMS.txt. `packaging\Stop-ProxyBridge-TestLab.ps1` завершает только этот экземпляр после окончания проверок; активную проверку сначала остановите в интерфейсе. Если порт 5178 занят другим пакетом, завершите тот экземпляр перед запуском.

Полное сравнение WFP и WinDivert выполняйте на одной версии лаборатории с одинаковыми параметрами. Старые отчёты Python-движка сохраняются; сравнение с новым движком справочное. В UDP-отчётах отдельно указаны заданная и фактическая подача пакетов. Удалённый режим в этом выпуске не дорабатывался.

Сравнение разделяет корректность обмена, полноту учёта маршрута и достижение темпа (допуск5%). Для новых прогонов ресурсы показаны по нагрузочным интервалам; архивные отчёты обозначены отдельно. Изменение памяти — последний минус первый замер, без рейтинга и относительного процента. Неполные/ненадёжные измерения не получают подсветку победителя. Показания CPU относятся к процессу клиента или всему ПК; полного учёта ресурсов драйвера здесь нет. Насыщение CPU стенда не подтверждает максимальную производительность клиента. Повторы одной сборки можно выбрать отдельными столбцами; медиана и диапазон доступны в подсказках значений.

Нагрузка: два локальных уровня LOW/HIGH с отдельными темпами по протоколам. Прикладные циклы содержат паузы; SFTP15/25циклов/с на соединение. Фон TCP6/10МиБ/с в каждом направлении, с изменением по интервалам стабильности. Maximum speed и масштабирование выделены явно. Это синтетические пользовательские профили, не модель всех приложений и не максимальная производительность клиента. Старые/новые условия численно не приравниваются.

Новые TCP-сеансы выполняют один подтверждённый обмен64байта на направление вместо обмена по времени. В сравнении CPU не подсвечивается победитель и не выводится относительный процент, если измерено меньше0.25CPU-с нагрузки; подробность доступна в подсказке. «Быстро»6с, «Обычно»30с, «Долго»120с; короткий режим не подтверждает устойчивые ресурсные различия.

Новые локальные прогоны дополнительно собирают выборки CPU в коде выбранного SYS и снимки paged/nonpaged pool по его тегам. CPU и пул общесистемные; это частичные наблюдения, без общих буферов Windows. CPU драйвера не складывается с CPU процесса. При недостатке выборок, потерях событий или неподтверждённой привязке CPU остаётся неизвестным, а не нулевым. Данные ядра не получают рейтинг победителя. ETW-сессия принадлежит попытке и завершается перед сохранением итогов; длительный прогон пока исключён из этого сбора.

Длительная проверка выполняется отдельно, с фиксированным циклом нагрузки: обычная работа, всплеск, создание соединений, затишье и восстановление. Доступны2/24/48/72часа; старые SHORT/NORMAL/LONG для этой проверки означают24/48/72часа. Постоянные TCP/UDP-каналы живут весь прогон; HTTP/HTTPS/HTTP2/SFTP/DNS-TCP/QUIC проверяются периодическими операциями. Ошибка канала остаётся в результате, остальные продолжаются после подтверждения изоляции; потеря контроля/неизвестный worker останавливает попытку. При отмене сохраняются частичные результаты; непрерывный тест не возобновляется после перезапуска. Данные пишутся в append-only журнал с SHA256 и ограниченную сводку. Постоянная трассировка ядра в этом режиме отключена; CPU/RAM процесса и общего ПК измеряются отдельно. Короткие проверки реализации не являются подтверждением успешного двухчасового или суточного прогона.
