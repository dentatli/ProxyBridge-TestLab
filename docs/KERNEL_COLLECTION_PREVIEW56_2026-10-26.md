# Наблюдения ядра для отдельных прогонов — preview.56

Реализован общий для WFP и WinDivert сбор `exclusive-ip-and-tagged-pool-v1`. Запуск остаётся прежним: пользователь отдельно выполняет одинаковые наборы и выбирает отчёты в таблице. Длительный прогон не изменён и исключён из нового сбора.

## Что измерено

Собственная realtime ETW-сессия на каждый сценарий, TraceEvent 4.0.0. Модуль выбран по имени SYS, PE-размеру/checksum/timestamp; SHA256 выбранного файла закреплён в отчёте. Учитываются только IP внутри выбранного модуля, не весь стек. QPC события распределяет задержанные события по границам фаз; после Stop потребитель дренируется. Исходный интервал профилирования сохраняется; изменение интервала, потеря событий, неоднозначность модуля или неполный drain запрещают CPU-оценку. Меньше30выборок — неизвестное CPU-время, не ноль. Это порог отображения, не гарантия статистической точности.

Память: снимки NtQuerySystemInformation(SystemPoolTagInformation), теги PBfp/PbDu или WDiv проверены в выбранном бинарнике. Область общесистемная; наблюдаемые максимумы paged/nonpaged и конец нагрузки в КиБ. Не резидентная RAM и не полный footprint: WDF/NDIS/общие Windows-выделения и возможные совпадения тегов не атрибутируются. CPU драйвера пересекается с процессным CPU; их не складывать.

Итоги сериализуются до raw SHA; summary сохраняет метаданные. Недоступность сбора не превращается в нулевой результат или ошибку трафика, однако неподтверждённая очистка останавливает очередь. Чужие ETW-сессии не останавливаются. CPU/память ядра — наблюдения без зелёного победителя и относительных процентов. Старые отчёты не получают вымышленных значений. Условия включают политику профилирования, поэтому старые/новые методы не приравниваются.
