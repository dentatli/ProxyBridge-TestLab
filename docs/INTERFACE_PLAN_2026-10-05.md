# Интерфейс лаборатории: сборки, наборы тестов и сравнение

Требования пользователя от 2026-10-05. Этот план заменяет одностраничный поток из INTERFACE_FLOW_2026-09-28.md. Это план реализации; новые страницы, произвольные сборки, наборы тестов и профили нагрузки пока не реализованы. RU/EN обязательны для всего пользовательского пути.

## Страницы

| Страница | Основные действия |
|---|---|
| Сборки | Добавить комплект ProxyBridge, выбрать тип driver / 4.0.0 и дать своё имя, например «актуал» или «бета». Выбрать сборку для тестирования. |
| Тестирование | Выбрать локальный/удалённый SOCKS5 и контролируемого получателя; отметить нужные тесты галочками; выбрать длительность и интенсивность. Сохранить набор для повторения на другой сборке. |
| Запуск | Короткая сводка сборки, тестов, условий и ожидаемого времени; готовность, явный запуск, текущий тест и прогресс, остановка с очисткой. |
| Результаты | Сравнить актуальные измерения выбранных сборок и показателей; отдельная вкладка «История» для предыдущих запусков. Ошибки корректности и сопоставимость видны рядом с итогом. |

Одна общая навигация и переключатель языка. Каждая страница имеет свой URL; длинного общего экрана нет. Возврат и обновление сохраняют выбор. Активный запуск виден на всех страницах и продолжается при навигации. Состояние задания принадлежит серверу; смена страницы не запускает и не останавливает измерение.

Основные действия и данные показывать кратко. Технические сведения, пути, хеши и диагностические журналы — в раскрываемых подробностях. Доступность определяется реально поддержанным backend; неподготовленные комбинации не выдавать за запускаемые.

## Сборка и пользовательское имя

Имя — удобная подпись, отдельная от типа продукта. «Актуал» и «бета» могут обе иметь тип driver. Предложить имя по умолчанию и разрешить переименование; выводить как текст, ограничить длину, не использовать как путь или команду.

Стабильный ID сборки связывает запись с фактически проверенными файлами CLI/Core/драйвера. Переименование не переписывает исходные свидетельства. При изменении файлов нужна новая проверка и новая ревизия сборки; старый результат остаётся привязанным к старым файлам. Репозиторий/ref/commit можно указать, но неподтверждённое происхождение не становится доказанным из-за подписи пользователя.

В истории хранить имя на момент запуска и ID сборки/ревизии; актуальное имя можно показать рядом. Одинаковые имена не объединяют разные бинарные комплекты. Один и тот же комплект под разными именами не считать двумя разными версиями продукта.

Выбор произвольной beta из GitHub требует адаптера совместимости и фактической проверки маршрута/жизненного цикла. Поле имени само по себе не снимает нынешние ограничения known kit. Версии до 4.0.0 не поддерживать. Между driver и 4.0.0 сохраняется согласованный порядок с перезагрузкой; два продукта одновременно не запускать.

## Выбор тестов и условий

Галочки обозначают реальные сценарии с понятными названиями:

- Задержка TCP без фоновой передачи.
- Задержка TCP при отправке/скачивании данных.
- Отправка TCP и скачивание TCP (раздельный выбор направлений).
- Обмен UDP: задержка, потери и правильность доставки.
- Три режима: ProxyBridge выключен / работает, тестовое приложение без правила / тестовое приложение через SOCKS5. Это отдельная галочка с собственной длительностью и нагрузкой.
- Много одновременных соединений и восстановление после нагрузки: TCP и UDP отдельно; подробности в [CONNECTION_STRESS_PLAN.md](CONNECTION_STRESS_PLAN.md). Это новый сценарий в плане, контроллер ещё не реализован.
- Длительная/смешанная работа и трафик без правила ProxyBridge — по мере подключения существующих и новых контроллеров.

Окончательное уточнение пользователя 2026-10-05: OFF / UNRULED / SOCKS5 не являются переключателями внутри остальных тестов. Отдельный тест «Три режима» выполняет все три пути в одинаковых условиях и показывает разницу. Длительность и нагрузка выбираются для этого теста целиком, а не отдельно для каждого пути. Остальные тесты сохраняют сравнение напрямую / SOCKS5; UNRULED в них не добавлять. Настройки длительности и нагрузки принадлежат каждому выбранному тесту, поэтому в одном наборе можно сочетать разные условия разных тестов.

CPU и RAM собирать вместе с выбранным тестом, если они доступны, и выбирать их отображение в результатах. Они не требуют отдельного повторного сетевого прогона. Явно различать процесс ProxyBridge/CLI, всю систему и вспомогательные процессы; не называть CPU CLI нагрузкой самого драйвера. Ватты пока не измеряются.

Длительность и интенсивность — независимые настройки. На первом этапе — проверенные пресеты, без произвольного ввода десятков параметров:

| Настройка | Предлагаемые варианты | Что должно быть зафиксировано |
|---|---|---|
| Длительность | Быстро / Обычно / Долго | Фактическое время или объём, прогрев, повторы и окно измерения каждого теста. |
| Нагрузка | Низкая / Высокая | Заданный темп, размер данных, число потоков и фоновые передачи; наблюдаемый прогресс. |

Численные параметры назначить при подготовке конкретных профилей. Нельзя механически назвать нынешний SMOKE «низкой нагрузкой», а STANDARD «высокой»: их старые условия сохраняются. Высокая нагрузка не означает автоматически максимальную пропускную способность. Для задержки без фоновой передачи неприменимую настройку нагрузки скрывать или ясно объяснять, какую интенсивность обмена она изменяет.

Каждая выбранная комбинация разворачивается в неизменяемый план с точными параметрами и версией методики. Один набор можно повторить для «беты» без повторного ручного выбора. Показать суммарную оценку времени до запуска. Прямой путь служит базой для накладных расходов; на основном экране достаточно краткой настройки «Сравнить с прямым трафиком» с доступностью по методике.

В отдельном тесте «Три режима» различать три пути: OFF — напрямую при выключенном выбранном ProxyBridge; UNRULED — напрямую при работающем ProxyBridge, процесс генератора вне правил; PROXY — процесс генератора по правилу через SOCKS5. UNRULED не подменять правилом DIRECT для уже перехваченного процесса: это другая траектория. Подтверждать активность продукта/драйвера, правила и фактический маршрут, сохранять точные условия и попеременный порядок режимов. Разница UNRULED−OFF оценивает влияние работающего продукта на трафик вне правил в данных условиях; PROXY−OFF оценивает весь выбранный прокси-путь, включая SOCKS5 и стенд, не только драйвер.

Прежние TCP SMOKE имеют только OFF/PROXY. В таблицу добавлены прямые RTT p50/p95/p99 и темп upload/download из того же подтверждённого результата; UNRULED этих серий показан как отсутствие измерения. Старые отдельные UDP UNRULED серии не подставлять в TCP-таблицу и не объединять с другими условиями. 2026-10-05 подготовлена отдельная короткая TCP RTT серия three_modes_readiness_v1 через Invoke-LocalTcpThreeModes.ps1: существующий RTT контроллер с opt-in ThreeModes, OFF/UNRULED/PROXY, 128 measured + 200 warmup на режим, owned socket snapshot до окна. Новый сценарий в Results/History — «Задержка TCP: выключен / без правила / SOCKS5». Реальный запуск/compile/API/UI этой ветки ожидают пользователя. Это фиксированный короткий порядок, не повторное причинное сравнение накладных расходов; transfer UNRULED и высокие/длительные профили ещё не подключены. Старые отчёты не менять.

Набор выполняется последовательно через существующие контроллеры, с общим эксклюзивным выполнением и проверкой между тестами. Сохранять результат каждого теста отдельно. Отмена сохраняет завершённые тесты и не превращает неполный набор в успешное полное сравнение. Ошибка маршрута/очистки останавливает дальнейший запуск; известный дефект корректности остаётся видимым отдельно от допустимых измерений производительности.

## Результаты и таблица

Уточнение пользователя 2026-10-05: история тестирования сохраняет предыдущие результаты, а выборочная таблица содержит только актуальные данные. На странице «Результаты» два раздела: «Сравнение» и «История».

«История» хранит все запуски с датой, сборкой/ревизией, тестами, фактическими условиями и статусом, включая ошибки, отмену и неполные серии. Фильтры: сборка, тест, длительность, нагрузка, топология, дата и статус. Можно открыть прежний отчёт и его подробности. Новый запуск не удаляет и не переписывает прежний. Исторические отчёты не добавляются в актуальную таблицу вручную.

«Сравнение» выбирает последний завершённый результат теста каждой выбранной сборки/ревизии при выбранных точных условиях и методике. Ключ включает фактическую идентичность сборки, сценарий/направление, параметры нагрузки/длительности, топологию и существенные условия измерения; одного display name недостаточно. Сохранять ID и дату выбранного прогона. Пока новый тест выполняется, прежнее измерение явно помечать как предыдущий результат с указанием нового запуска в работе, не выдавать его за уже обновлённое.

Если последняя завершённая попытка в этой группе FAILED/CANCELLED/INCONCLUSIVE либо не содержит нужной подтверждённой метрики, не подставлять молча более старый успешный результат. Показывать актуальный статус/«Нет достоверных данных»; старый успех доступен в истории. Оценка корректности и допустимость отдельных показателей производительности остаются раздельными по существующей методике: известный дефект не скрывать, разрешённые доказанные измерения показывать с предупреждением.

Все выбранные показатели одного теста брать из одного выбранного результата, не собирать RTT из одного запуска, CPU из другого и RAM из третьего. Для набора тестов допускаются последние результаты каждого теста отдельно, с сохранёнными датами/ID; это не выдаётся за единый одновременный запуск. После изменения файлов новый комплект не наследует измерения прежней ревизии, даже если имя осталось «бета». Для разных условий — отдельные результаты и оценка сопоставимости, без усреднения старых и новых серий.

Выбор метрик галочками: RTT p50/p95/p99, потери/ошибки, скорость отправки/скачивания, CPU и RAM с указанием области и способа агрегации. Предлагать только фактически собранные метрики. Максимум RAM и среднее RAM нельзя подменять друг другом; аналогично для CPU и задержки.

Пример структуры (без выдуманных измерений):

**Задержка TCP под нагрузкой · Долго · Высокая нагрузка**

| Показатель | актуал | бета | Разница беты к актуалу |
|---|---|---|---|
| RTT p95, мс | значение | значение | мс и % |
| CPU ProxyBridge, среднее, % ПК | значение | значение | процентные пункты |
| Private RAM ProxyBridge, среднее, MiB | значение | значение | MiB и % |

«Высокая нагрузка» — условие таблицы, а не отдельная строка измерения. Если пользователь хочет показать достигнутый темп/число потоков, это отдельные подписанные показатели. Прямые измерения и добавка к прямому RTT доступны как выбранные столбцы/метрики; по умолчанию таблица остаётся короткой.

Под таблицей короткий итог корректности и сопоставимости. Проверять точные параметры, методику/инструменты, топологию/получателя/прокси, правила, прогрев, повторы, машину/ОС и происхождение выбранных результатов. Одни и те же названия пресетов не доказывают одинаковые условия. Разные версии продукта ожидаемы и не являются сами по себе препятствием для сравнения.

При разных условиях разрешать просмотр рядом с понятной пометкой «Условия различаются» и причиной, но не выводить разницу как подтверждённое улучшение продукта. Не объединять различные профили в одну среднюю цифру. Непроверенные/неполные измерения показывать как отсутствие данных; исторические дефекты 4.0.0 и UDP сохранять. Старые отчёты не переписывать и не требовать их повторения ради UI.

## Порядок реализации

1. Разнести существующий рабочий UI по четырём страницам, сохранив API/DPAPI, текущие контроллеры и историю. Все текущие состояния и ошибки остаются доступны.
2. Добавить каталог именованных сборок и привязку выбранной ревизии к плану/результату. Подготовить миграцию нынешнего одиночного выбора, не теряя старые результаты.
3. Создать единый каталог сохранённых измерений, отдельную историю всех запусков и таблицу только актуальных результатов/выбранных метрик; переиспользовать строгие текущие проекции и saved-data агрегаторы. Не подставлять старый успех при последней неуспешной попытке. Старые условия показывать точно, не назначать им задним числом новые пресеты.
4. Галочки двух текущих тестов и нормальная последовательность набора уже подтверждены пользователем. Текущий приоритет — независимые длительность/нагрузка для выбранного теста, отдельный тест «Три режима» с такими же настройками и тест насыщения соединениями с проверкой восстановления. Подключать реальные параметры контроллеров и строгую оценку, а не только элементы UI. Не добавлять UNRULED во все тесты и не подменять длительные/высокие профили прежними короткими проверками.
5. Подключать другие комплекты driver, 4.0.0, удалённый режим, высокие/длительные нагрузки после подготовки соответствующих runtime-адаптеров. Проверка пользовательской GitHub-сборки остаётся итоговой практической проверкой лаборатории.

Проверять изменения соразмерно: исходный код/метаданные и ручная проверка пользователем в UI. Бесполезные автотесты не добавлять; успешные бенчмарки не повторять ради оформления. Полноценная возможность «актуал / бета» зависит от пунктов 2–5, а не только от новой таблицы.
