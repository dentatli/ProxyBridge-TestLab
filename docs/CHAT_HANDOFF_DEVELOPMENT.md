- Сохранить одобренный интерфейс отдельных страниц: сборки, тестирование, запуск, результаты с историей. RU/EN — весь пользовательский путь.
- Выбор реальных тестов галочками; длительность и нагрузка отдельно для каждого теста; оценка времени каждого теста и общего набора. «Три режима» — самостоятельный тест OFF / UNRULED / SOCKS5 с одинаковыми условиями трёх путей, не переключатели остальных тестов.
- Соединения TCP: ступенчатая нагрузка и восстановление. Не выдавать достижение заданного числа соединений за доказанное переполнение внутренней таблицы или максимальную ёмкость. Фактические отказы показывать и сохранять.
- Пользовательские имена сборок, например «актуал» и «бета», с привязкой к реальной идентичности/ревизии бинарного комплекта; история всех запусков. Выборочная таблица использует последний запуск выбранной сборки и условий, без подмены ошибки/отмены прежним успехом; разные условия не смешивать. Пользователь выбирает сборки и показатели, включая задержку, CPU и RAM с правильной областью измерения.
- Ubuntu: выбор удалённого узла → отдельный SSH-ключ TestLab и public key для root authorized_keys → IP/необязательный порт → «Автоматическая настройка» либо «Проверить соединение» для уже готовой машины. Приватный ключ вне Git/отчётов. Готовность требует проверенного обмена и компонентов, не только SSH-входа. Потеря связи блокирует запуск, backend повторно проверяет условия. Только последние Ubuntu; точную матрицу выпусков закрепить до реализации платформенного допуска.
- Весь каталог подключать по фактической поддержке backend и свидетельствам маршрута. Нельзя сделать неподтверждённый сценарий «готовым» снятием проверок. Навигация, обновление страницы, остановка, очистка, ошибки и история должны работать согласованно.

## Порядок работы и границы

Начать с инвентаризации и оставшегося функционала, затем завершать рабочие пользовательские сценарии. Обычные проверки ожидаемой длительности менее пяти минут разрешены; длительный набор не дробить ради обхода лимита. Проверки с ProxyBridge/трафиком согласовать с диагностикой на общей VM. Отдельный worktree разделяет исходники, но не ОС, драйвер и отладчик.

Длинный прежний контекст сохранён в [истории](history/AGENTS_CONTEXT_2026-10-08.md), читать выборочно. Не переносить временные запреты диагностического Run на обычную разработку приложения, но не менять BCD/драйвер/WinDbg ради неё. Не менять диагностические scripts/debugger, frozen kits и журналы в рамках этой задачи. Если общий контроллер нужен обоим чатам, согласовать пересечение до его изменения.

Изменения исходников/документации коммитить и пушить, проверяя результат; приватные captures, kits, SSH-ключи и credentials не добавлять в Git. Текущий прогресс записывать здесь или в профильных планах, не наращивать AGENTS.md историческими NEXT. Отчитываться по реально проверенным результатам и ограничениям.
