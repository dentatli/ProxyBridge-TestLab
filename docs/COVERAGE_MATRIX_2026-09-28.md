# Матрица покрытия и приоритеты

Срез 2026-09-28. Основа: текущие `scenarios/**/*.json`, `config/traffic-capability-model.json`, [описание ProxyBridge](https://github.com/InterceptSuite/ProxyBridge) и [документация Windows](https://interceptsuite.com/docs/proxybridge/configuration-windows/). Это план проверки, а не результат нового запуска ProxyBridge.

## Как читать статусы

В текущих файлах найдено **196 уникальных записей**: 167 `EXECUTABLE`, 17 `CAPABILITY_GATED`, 5 `SYSTEM_CHECK`, 7 `UNSUPPORTED_PRODUCT_SCOPE`. Это статусы *контрактов TestLab*, не число успешно пройденных проверок продукта. Старые документы называют 135 записей, потому что относятся к прежнему срезу каталога. Опубликованные реальные результаты охватывают только **25 IPv4-сценариев** на ProxyBridge 4.1.0-Beta WFP в конкретной Windows VM; они не подтверждают остальные записи и не являются результатом этой машины. Источник: `docs/test-results.md`.

Для каждого измерения дополнительно фиксировать четыре независимых признака: **заявлено продуктом**, **есть исполняемый контракт TestLab**, **среда готова**, **реально проверено на версии**. В интерфейсе слово «проверено» допустимо только для последнего признака.

## Обязательные измерения матрицы

| Ось | Варианты | Правило покрытия |
|---|---|---|
| Маршрут | DIRECT, BLOCK, PROXY | Первые два — контроль корректности; для PROXY нужно доказательство выбранного proxy config и внешнего маршрута |
| Транспорт | TCP, UDP | UDP `PROXY` проверяется только при SOCKS5 с подтверждённым UDP ASSOCIATE |
| Прокси | SOCKS5, HTTP | HTTP-прокси с UDP-правилом `PROXY` по документации ProxyBridge отправляет UDP напрямую: не показывать такой прогон как UDP через прокси |
| Размещение прокси | На Windows-ПК, удалённый | Различать задержку ProxyBridge, прокси и сети; расположение получателя выбирать отдельно |
| IP | IPv4, IPv6 | Только если есть маршруты и поддержка всех участников цепочки; метки `SKIPPED_CAPABILITY` объяснять пользователю |
| Правила | Процесс, адрес, порт, порядок, несколько прокси | Достаточно базовой серии плюс выборочные пересечения и отдельные регрессии, не декартово произведение всех значений |
| Нагрузка | Короткая операция, длительная передача, параллельная, смешанная, soak | Один и тот же протокол может иметь разные профили, их результаты не смешивать |
| Результат | Корректность, скорость, потребление ресурсов ПК, стабильность | Отдельные вердикты и доказательства; наличие сценария в каталоге не равно измерению |

Особый случай локального получателя: localhost в ProxyBridge по умолчанию идёт напрямую. Для измерения PROXY нужен наблюдаемый путь через прокси и проверенный доступ к получателю; простой запрос к `127.0.0.1` не подходит как доказательство. Это следует из [документации Windows](https://interceptsuite.com/docs/proxybridge/configuration-windows/).

`ICMP`, `IGMP`, `GRE`, `ESP/AH`, `SCTP`, raw sockets и канальный Ethernet помечены вне заявленной области продукта в текущем каталоге. Пересматривать при изменении официального контракта ProxyBridge, не записывать как дефекты TCP/UDP-проксирования.

## Порядок реализации

1. Для первой версии выбрать доступные генератор и получатель, которые действительно проходят через ProxyBridge в обоих размещениях прокси. Упростить выбор в UI.
2. Получить честный TCP A/B и базовую проверку UDP-маршрута. Не ждать завершения всех 196 контрактов для первого полезного отчёта.
3. Добавить DNS, QUIC/HTTP3, интерактивный UDP, смешанную и длительную нагрузку по готовности каждого прокси. Отдельно показывать ограничения HTTP-прокси и SOCKS5 без UDP ASSOCIATE.
4. Дальше закрывать пробелы по официальному продукту: SFTP, RDP, базы данных и остальные прикладные семейства. Для каждой новой версии ProxyBridge заново фиксировать фактический результат.

Для определения приоритетов не писать автотесты кода TestLab. Реальные тесты трафика ProxyBridge — предмет проекта и выполняются отдельным согласованным запуском.
