## Что подтверждено

Текущий fwpkclnt загружен по fffff8026aaa0000, символы PDB доступны. Live call из TCP/IP заканчивается непосредственно перед `WfpAleAuthorizeAccept+0xcaf`, адрес возврата fffff8026a75567b. Это устраняет неоднозначность дискового IAT call с последующим NOP. Подтверждены prologue и сохранение регистров: caller RBP на rsp+58h, caller RBX на +60h, return на +68h, caller RDI на +78h. Значения этих слотов новой action пока не читались на target.

Сообщение `Unable to load image ... NETIO.SYS` относится к недоступному локальному образу для отладчика. Оно не доказывает неисправность NETIO в VM. Его внутренний код здесь не исследован. Live-листинг разрешает вызов WfpNblInfoGet и имя сравниваемого sentinel MmBadPointer.

## Новый кандидат

Профиль: `scripts/debugger/pb-kd-lookup-two-miss-candidate-20261018.json`, метод `kd-lookup-two-miss-candidate-20261018-v1`. Планируемые active IDs в JSON описывают будущий профиль, а не текущее состояние WinDbg. Последний console показывает старые 2/3 отключёнными и отдельный g.

| ID | Новое место | Условие события | Что различает |
| --- | --- | --- | --- |
| 2 | FwpsNetBufferListRetrieveContext0+f3, fffff8026aaa3223 | RSI=5 | WfpNblInfoGet вернул NULL либо MmBadPointer |
| 3 | FwpsNetBufferListRetrieveContext0+22e, fffff8026aaa335e | RSI=5, R14B=0 | Общий поиск не нашёл подходящую запись |

Обе точки заменяют прежние 2/3; третьей активной точки не добавляется. Место +22e посещается также при успешном общем поиске: условие сокращает вывод, но не debugger traps. Снижение тормозов не проверено и не обещается.

Action сначала проверяет доступность return-slot и точный caller, затем диапазон сохранённых регистров, затем четыре байта caller ports. Только после guards читает endpoint, NBL и порты. Caller local_raw должен быть da84 (34010). EBP — callee consume flag; caller RBP берётся из сохранённого слота. state_raw печатается без разыменования: это не доказанно живой объект. scope/RSP и NBL pointer не уникальные идентификаторы жизни соединения/пакета. Недоступное чтение даёт UNREADABLE и неполное покрытие; gc находится вне условий.

Проверены ASCII, структура условий, порядок guards, восемь printf arguments и однократное экранирование вложенных кавычек для bp. Это офлайн-проверка, не исполнение WinDbg parser и не runtime-проверка стековых чтений. Узкий старый retrieve-stage validator к этому профилю не применялся. Исполняемый stage и ZIP не создавались.

## Стоп и следующий шаг

Только USER регистрация новых 2/3 с немедленным bd каждой точки, затем bl/.bpcmds и отдельный g даже при ошибке. Перед Break и каждым bp предупредить: вся VM, Codex и RDP могут остановиться; новый bp сначала включён. Команды по одной. При неожиданном inventory или ошибке прекратить замену, bd2/bd3/bl/g отдельно, прислать вывод. Старый staging повторно не загружать. Ни be, ни Run на этом шаге.

После подтверждения регистрации нужен отдельный новый комплект и проба на четырёх соединениях. Старые kits не подходят. Успешная проба без miss не проверит исполнение тела обеих failure-actions. Новый профиль различает группы отказа, но не устанавливает предшествующую причину: никогда не прикрепляли, ранее потребили, удалили или потеряли. Для этого нужна история конкретного lifetime. 10061 остаётся вне активного расследования.
