Вместо парных полос — одна таблица. Слева проверки и группы показателей, в столбцах до четырёх сохранённых прогонов. По умолчанию последние два; пользователь добавляет/удаляет столбцы (2–4), выбирает прогоны в шапке. Повторный выбор одного отчёта заблокирован; prefs нормализуются до4. Фильтр всех/одной из10 групп, «Ещё отчёты» использует прежнюю пагинацию. Выбор и фильтр сохраняются в sessionStorage. Нет новых сетевых сценариев.

Скриншот после прокрутки подтверждает, что названия и даты остались видны. Селекторы не пересоздаются при смене выбранного прогона/обычном обновлении данных; фокус и scroll сохраняются. Строки: группа → этап со статусом/длительностью/нагрузкой → условия → метрики по разделам. Missing=—, настоящий0 остаётся0. Под числами разница к первому столбцу; несовпадающие условия явно названы и разница справочная.

Лучшие значения выделены зелёным+«✓ Лучшее» только если во всех выбранных доступных столбцах есть PASS/cleanup, числовое значение и совпадают условия. Missing stage/unloaded report/FAIL/runtime mismatch не ранжируются. Скорость выше лучше, latency/loss/resources ниже лучше; предложенное число пакетов/транзакций/пик соединений не трактуются как победа. При равенстве отображаемых значений победителя нет, совместные лидеры выделяются вместе. Продуктовая identity по-прежнему переменная сравнения; метод/среда/очередь/нагрузка/duration guards сохранены.

Новый модуль lab-comparison-table.js; старый renderRunComparison/plot и неиспользуемые стили полос удалены, имя renderRunComparison сохранено для вызовов основного UI. Отчёты, раскрываемые этапы, JSON/логи и engine не менялись.
