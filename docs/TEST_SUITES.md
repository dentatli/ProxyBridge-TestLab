Изменение файлов требует новой подготовки.

BenchmarkRunService исполняет дочерние wrappers последовательно и ждёт завершения каждого процесса, журналов и результата/cleanup. Штатная file lease удерживается внутри каждого теста; UI считает набор активным и между тестами. Это не новая глобальная блокировка внешних ручных запусков на всю очередь. Если другой executor занимает штатную lease, запуск не считается успешным. Методика, native generators, helpers, Core и драйвер не изменены.

Остановка под gate сохраняет запрос набора и marker активного дочернего контроллера. Он заканчивает текущий прогон и cleanup; последующие тесты не стартуют. При ошибке очередь заканчивается FAILED. При остановке до завершения всего набора — CANCELLED. Если последняя операция полностью завершилась после запроса остановки, набор может быть COMPLETED; это не принудительное завершение процессов.

Для не достигнутых очередью тестов создаются отдельные history jobs CANCELLED / SUITE_TEST_NOT_STARTED, ноль прогонов, без controller receipt или измерений. Поэтому актуальная таблица не подставляет старый PASS. Успешные уже завершённые тесты сохраняются. Набор не становится дополнительным доказательством сопоставимости разных тестов/сборок.

Перезапуск приложения не возобновляет очередь. Незавершённый suite помечается INTERRUPTED; отдельные дочерние процессы обрабатываются прежним stop-marker/reboot механизмом. Не начатые tests получают записи без измерений. Wrapper дополнительно учитывает INTERRUPTED suite в cross-boot guard. Не запускать новый набор, игнорируя требование перезагрузки.
