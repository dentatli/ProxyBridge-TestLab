После принятия запуска все карточки сложены. По событиям runner текущая раскрывается, предыдущая сворачивается. Ручной выбор открытия/закрытия имеет приоритет; сохраняется в sessionStorage для текущего run ID, в том числе при смене языка/перезагрузке. Обновление статусов не пересоздаёт карточки. Синий — выполнение, зелёный — успех, красный — FAIL, янтарный — PASS и FAIL внутри одной группы, серый — ожидание/пропуск; текст и значки дублируют цвет. Перед итоговой очисткой успех этапа обозначен предварительным. Отдельная последняя карточка показывает остановку клиента и освобождение получателя. Подробности остаются в отчётах/логах.

Local runner публикует небольшой `queue-state.json`: только run/case IDs, параметры, readiness, phase и краткие результаты. `client_ready` выставляется после подтверждённого UNRULED control, не по факту запуска процесса. Файл служит только интерфейсу, не изменяет evidence gates, continue policy, правила и итоговый отчёт. Ошибка записи представления не влияет на тесты. Backend ограничивает размер/глубину JSON, не читает private binding, сохраняет последний snapshot после завершения. Результаты после окончания берутся из итогового отчёта. Remote runner не расширялся; без новых local milestones готовность не выдумывается.
