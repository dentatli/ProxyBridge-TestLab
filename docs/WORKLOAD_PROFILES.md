Три отдельные галочки: задержка TCP, передача TCP, «Три режима». У каждой независимые длительность и нагрузка. «Три режима» выполняет OFF / UNRULED / SOCKS5 в одинаковых условиях. У остальных тестов только напрямую / SOCKS5.

| Длительность | TCP: объём на соединение при низкой / высокой нагрузке | TCP RTT: измерений на путь при низкой / высокой нагрузке |
|---|---:|---:|
| Быстро | 64 / 512 MiB | 128 / 256 |
| Обычно | 256 / 2048 MiB | 1500 / 3000 |
| Долго | 960 / 7680 MiB | 6000 / 12000 |

TCP передача: низкая нагрузка — лимит отправителя 8 MiB/с, высокая — 64 MiB/с. Объём соответствует номинальным 8 / 32 / 120 секундам при достижении лимита. Фактическая длительность включает открытие, проверку данных и завершение. Одна пара напрямую / SOCKS5 на направление, четыре переноса. ctsTraffic остаётся исходным; verify:data и одинаковый shutdown:rude сохранены. Штатное закрытие TCP не проверяется, максимальная скорость не заявляется.

TCP RTT и «Три режима»: нагрузка означает интенсивность последовательных запросов — пауза после ответа 20 / 10 мс, один запрос в полёте. Фоновой передачи нет; это не тест полной загрузки CPU/канала. Длительность задаётся объёмом обменов, не точным таймером. Измеренное время зависит от RTT и Windows Sleep. 1000 прогревочных обменов на путь исключаются; они дают время наблюдать принадлежащий запуску сокет до первого измеренного запроса. Если проверка не успела, результат INCONCLUSIVE. Нативный генератор не изменён, лимит 20000 записей не превышен.

Для этих пресетов действует method controlled-workload-v1; отдельная трёхрежимная серия имеет stage three_modes_workload_v1. Внутренний совместимый контейнер контроллера остаётся SMOKE/одна пара, но workload_preset полностью задаёт новую методику и отображается как WORKLOAD. Прежним SMOKE не присваиваются новые настройки задним числом. Каталог и модуль заморожены SHA в плане; параметры проверяются по фиксированным значениям версии методики в PowerShell, C# и Python. Изменение чисел требует новой версии метода.

Перед запуском и каждым тестом прежние file/kit/runtime/lease/crossboot gates остаются обязательными. Native deadline — 600 секунд на перенос/обменный прогон; watchdog proxy/sampler — 720 секунд. Отмена дожидается завершения текущего прогона и очистки, затем пропускает остальные. Это может быть несколько минут в длинном профиле. Core, драйвер, native generators и копирование сетевых данных не изменены. У SOCKS5 helper расширена только допустимая граница watchdog до720 секунд.

В «Результатах» выбираются длительность + нагрузка либо «Прежние короткие проверки». Последняя попытка выбирается внутри этих условий; метрики берутся из одного подтверждённого результата. Ошибка, отмена и незапущенный тест не заменяются прежним PASS. Фактические source/tool conditions_key продолжают определять сопоставимость; одинаковые названия пресетов её не доказывают. История содержит прежние и новые попытки.
