# Единая диагностика маршрута и нескольких гипотез

Подготовлен отдельный комплект `tcp-redirect-context-preparation-20261006-114601-c11a4ded`.
Три варианта выполняются одной командой Run, после одной установки диагностического драйвера и одной ручной перезагрузки. Это диагностические условия, не сравнение скорости и не исправленная пользовательская сборка.

| Вариант | Очередь listen | Дополнительное ожидание |
|---|---|---|
| original | Исходный SOMAXCONN | Нет |
| backlog1024 | SOMAXCONN_HINT(1024) | Нет |
| backlog1024-delay650 | SOMAXCONN_HINT(1024) | Один раз 650 мс после готовности к чтению, до первого IPv4 accept |

В каждом варианте один процесс CLI проходит 4 → 64 → 256 → 640 → 4 соединения. Восстановление проверяется без перезапуска CLI внутри варианта. Между вариантами процессы завершаются, проверяется очистка, затем запускается следующий вариант. Неполная запись или ошибка очистки останавливает серию; штатно записанные отказы продукта сохраняются и позволяют перейти к следующему варианту.

## Покрытие наблюдениями

| Участок / гипотеза | Наблюдения и проверка |
|---|---|
| Создание native соединения | Реальная командная строка, PID, API подключения, ограничение 32 ожидающих попыток, CSV с адресами/результатом/проверенными байтами |
| Выделение и назначение контекста WFP | Существующие записи отдельного ядра: классификация, статусы Acquire, выделение NULL/non-NULL, исходные и переписанные адреса, target PID, границы void Apply |
| Очередь слушателя / отказ первого SYN | Общая TCPIP трасса: SYN, transport-drop с причиной, retry, connect-complete и Windows accept; сравнение original и backlog1024 |
| Контекст теряется из-за ожидания | QPC начала/конца реального ожидания 650 мс, accept-return и исходный query entry/exit; связь с нужным native соединением и отсутствие SYN-drop/retry обязательны |
| Core → SOCKS5 | Новые ROUTELEG записи связывают принятый socket/native peer с исходящим socket, его локальным/удалённым адресом, результатом connect и SOCKS5-handshake |
| SOCKS5 → получатель | TCPIP события второй стороны, события контролируемого SOCKS5-получателя, идентификаторы соединений и проверенная передача; конечное связывание выполняется при разборе трассы |
| Ресурсы / восстановление / лаборатория | Исходные проверки свободной памяти/диска, сэмплер, до/после нагрузки, collector/helper/CLI exit и сохранённые подтверждения очистки |

`ROUTELEG.api_error` содержит исходное состояние WSA до метаданных. При успешном API оно может быть старым и само по себе не является ошибкой. Для SOCKS5 учитывается также исходный результат протокольного handshake. Снимки адресов восстанавливают исходное WSA состояние; дополнительных запросов контекста нет.

Одна общая ETL: те же 16 TCPIP event ID, предел сохранённой сырой трассы 32 MiB, без провайдера содержимого пакетов. Core записывает максимум две ROUTELEG строки на соединение; парсер ограничен 4000 строками на вариант. После Run обязательно проверить потери ETW, часы QPC и уникальное сопоставление PID/tuple/фазы/времени жизни TCB. Сообщение `...TRACE_PENDING` означает, что это сопоставление ещё не выполнено.

Внутреннее хранение контекста Windows непосредственно не наблюдается. Запись void Apply не доказывает удержание контекста; переполнение собственной таблицы драйвера не считается доказанным. Если original не воспроизведёт отказ или задержка не связана с нужным соединением без повторного SYN, соответствующий причинный вывод останется неопределённым. Никаких nearest/order fallback или превращения native отказа в PASS.
