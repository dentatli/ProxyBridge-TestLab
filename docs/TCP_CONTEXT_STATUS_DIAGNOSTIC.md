# Диагностика исходного NTSTATUS после повторного SYN

Серия пользователя 174009 завершена и разобрана офлайн: все 96 исходных ошибок Winsock 10022 имеют **STATUS_NOT_FOUND (C0000225)**. Windows не возвращает запись контекста для принятого сокета, и Core закрывает его до подключения к SOCKS5. Триггер подтверждён: SO_PAUSE_ACCEPT → отказ первого SYN → retry → запрос без контекста. Внутренняя операция переноса/освобождения записи Windows ещё не наблюдалась; ошибка Windows или собственного драйвера не объявлена доказанной.

Исходная очередь: 96 отказов из 968; очередь 1024 и очередь 1024 с фактической задержкой перед accept 659,277 мс: по 0 из 968. Все 2808 успешных соединений проверены по трём участкам маршрута и данным, всего 1404 MiB. Новый сбор использовал те же Core/sys/CLI, без hooks и дополнительных context-запросов; это диагностика, не сравнение скорости и не исправление поддерживаемого продукта.

Полный актуальный анализ: [analysis.md](../artifacts/diagnostics/tcp-context-status-review-20261006-174008/analysis.md), [validation.json](../artifacts/diagnostics/tcp-context-status-review-20261006-174008/validation.json). Предыдущий статический анализ сохранён в artifacts/diagnostics/tcp-context-retention-review-20261006-121256/analysis.md.

Использованный комплект: artifacts/diagnostics/tcp-redirect-context-preparation-20261006-172202-6d951b52; сохранённый Restore проверен. Старый verification/HANDOFF.md описывает уже выполненную подготовку, не следующий запуск. Промежуточный 171215 не использовать; frozen планы не пересоздавать. Нового запуска не подготовлено.

Реальная эмиссия подтверждена: 96 уникальных PID/TID/raw-QPC совпадений внутри исходных query entry..exit, LostEvents=LostBuffers=0. Предварительное предположение о 20 байтах payload исправлено **только в новом офлайн-аудите**: GUID сообщения находится в EVENT_HEADER.ProviderId, а payload содержит ровно четыре байта little-endian NTSTATUS. Raw ProcessTrace, xperf и Get-WinEvent согласованы. Исходные receipts и старые matcher/plans оставлены без изменения.

Следующий недоказанный шаг — адресный жизненный цикл приватной endpoint-записи при первом отказанном SYN и повторе. Публичные события этой трассы его не показывают. Повтор того же прогона не решит этот пробел; увеличение очереди подтверждено как диагностический контроль, не как проверенное окончательное исправление.
