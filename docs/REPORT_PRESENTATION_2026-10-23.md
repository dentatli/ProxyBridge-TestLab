## Группы и действующее сравнение — preview.25

Промежуточный PROVISIONAL в очереди теперь подписан «Успешно» сразу после успешного этапа, как и финальный PASS. Внутренний статус/evidence gates и зависимость итогового отчёта от cleanup не менялись; очистка остаётся отдельной карточкой. Это исправление подписи, не объявление предварительного результата итоговой приёмкой.

Показатели этапа разделены линиями: «Трафик», «UDP» (когда есть), «ProxyBridge», «Весь ПК», «Нагрузка и восстановление». Средний CPU и пиковые memory/handles/threads подписаны явно. Убраны общая занятая Windows RAM, повторяющиеся OS CPU/RAM получателя, ресурсы worker/origin process, нулевой счётчик подготовки и повторяющиеся значения скорости/RTT под нагрузкой. Общая RAM~7,4GiB была памятью всех процессов/ОС, не затратами продукта. Сырой отчёт/логи/JSON сохранили всё. Общий CPU ПК оставлен с уточнением про фоновые приложения. Нет новых измерений или изменения сохранённых данных.

Причина пустого сравнения установлена на сохранённых отчётах: различались local_runtime_sha256, queue_profile_sha256, case_position_in_queue (а иногда duration/load). Прежний UI целиком скрывал графики при любом таком различии. Теперь доступны отдельные значения A/B и полосы, в том числе наблюдения FAIL с явным статусом. Пропуск одной стороны=«—», не0. Общие причины выводятся один раз, различия конкретного этапа — в его карточке. Дельта/проценты только при прежних matching-conditions+PASS+cleanup gates. Старый CLI и новая Core session не становятся сопоставимыми. UDP показывает отправленные/принятые пакеты, RTT и потери вместо нулевой TCP-скорости.

Исправлена независимая ошибка критерия: adapter_id/product_contract/product_version, как и build_sha256, являются переменной сравнения самого продукта, поэтому исключены из ключа условий. Метод/ресурсный scope/версия лаборатории/машина/ОС/режим/нагрузка/длительность/очередь остаются в ключе. Это позволяет сравнить будущие WFP/WinDivert или ревизии при одинаковой измерительной среде, не смешивая разные лаборатории/методы. Реальный WFP runtime не запускался и не заявляется готовым.
