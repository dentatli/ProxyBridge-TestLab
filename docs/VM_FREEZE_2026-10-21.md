После загрузки исследованы существующие логи; debugger и нагрузка не запускались.

- После boot kd/WinDbg/KernelReadCapture/tracerpt не работают. Около 4.29 GiB

## Вывод и стоп-точка

Дополнительный осмотр существующих журналов: предыдущий Codex desktop log
заканчивается в 22:08:19 +05:00, вскоре после запуска kd. В конце есть
ResizeObserver warnings и обычные записи, без сообщения о причине зависания
ОС. Последняя запись старой CoS session — 22:06:56. Это только границы
сохранённых журналов, не замеры загрузки и не доказательство виновного процесса.
Тип гипервизора запрошен у пользователя для выбора журналов физического хоста.

Главная рабочая версия — сбой/истощение ресурсов в пути запуска debugger и
его перенаправления вывода. Временная связь и 1450 делают его подозреваемым,
но причина зависания всей VM и конкретный ресурс не доказаны: нет предаварийных
счётчиков, kernel dump или данных гипервизора. Падение пользовательского
KernelReadCapture само по себе не доказывает причину зависания ОС.

Не запускать снова KernelReadCapture или прежний hidden kd с redirected output
для воспроизведения. Не возобновлять сетевые тесты во время разбора VM.
Исходник KernelReadCapture.cs остался untracked и непригоден для использования;
private binaries/logs сохраняются. Для дальнейшего установления причины нужны
существующие журналы гипервизора физического хоста вокруг 22:08 +05:00 или
имеющиеся предаварийные измерения, а не ещё один запуск в этой VM.
