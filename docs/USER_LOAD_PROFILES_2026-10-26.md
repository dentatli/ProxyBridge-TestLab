# Пользовательские профили нагрузки — preview.54

Scope: «На этом ПК», одинаковая нагрузка для WinDivert и WFP. Всего два уровня: LOW — умеренно активная работа, HIGH — интенсивнее. Это явные синтетические профили лаборатории, а не статистически измеренная модель всех пользователей. Практический ориентир интенсивности 75/125; целочисленные соединения и специальные проверки масштабирования имеют собственные значения.

- Длительности отдельных окон SHORT/NORMAL/LONG: 6/30/120 секунд. Длительный прогон: 24/48/72 часа. Нагрузка не заменяет длительность или полноту выбора.
- Обычные прикладные проверки: два соединения, паузы между подтверждёнными циклами; HIGH повышает темп примерно в 1.67 раза. Размер полезных данных по умолчанию 512 байт, payload sweep остаётся 64/512/4096 байт. SFTP — цикл работы с маленькими объектами в памяти, не дисковый benchmark и не bulk-file throughput. Mail — синтетическая проверка протокола, не частота работы человека с почтой.
- TCP-фон LOW/HIGH: суммарно 6/10 МиБ/с **в каждом направлении**, разделён на 3/5 потоков. UDP mixed/stability: 3/5 потоков ×75 пакетов/с, payload512B. Probe — одно соединение 15/25 обменов/с. Нет адаптации нагрузки под измеряемую сборку.
- Stability/soak TCP-фон по интервалам: 50/100/125/100% с повторением. LOW 3/6/7.5/6, HIGH 5/10/12.5/10 МиБ/с в каждом направлении. UDP и probe постоянны: так видна реакция на изменения фона. Это управляемая смена интервалов, не случайные микровсплески.
- Maximum speed и масштабирование явно обозначены специальными проверками. LOW там не обещает ненасыщенный CPU. Maximum speed без ограничения темпа; TCP/UDP concurrency до128/192 потоков предназначено для проверки масштабирования.
- Byte target и session-rate target теперь участвуют в load quality. Отправка/получение и транзакции имеют разные единицы, не смешиваются в одном числовом показателе. Достижение темпа по-прежнему проверяется с допуском5%; потеря/route/capture/cleanup gates не ослаблены.
- Новый method `user-workload-v1` и runtime fingerprint исключают численный допуск старых/новых условий. LOW/HIGH и 51 атомарный ID сохранены, 10 общих карточек, совместимость импортируемых наборов сохранена. Удалённые планы проверены на равенство прежним: новые локальные настройки их не изменяют.

## Сброс лаборатории

По явному запросу пользователя активное хранилище `%LOCALAPPDATA%/ProxyBridge-TestLab` целиком перемещается в защищённый архив вне приложения. Новый store пуст: настройки, каталоги сборок/наборов, история, runtime/evidence/jobs. Browser state привязан к идентификатору store; явный reset сбрасывает только ключи `testlab-*` этого origin. При первом обновлении существующего store без запроса reset браузерные настройки сохраняются. Установленные продуктовые драйверы, служба, системные сертификаты, BCD и исходные продуктовые комплекты не удаляются. Frozen kits/captures и старые immutable packages сохраняются. Сброс не объявляет старые файлы невосстановимыми и не публикует архив.

Проверки и установленное состояние фиксируются в [актуальном checkpoint](LOCAL_APP_CHECKPOINT.md). Полные продуктовые прогоны после смены профиля выполняет пользователь; component gate не является подтверждением прохождения всех сценариев ProxyBridge.

У всех exchange/route/windows PASS и loadMET; signed origin/native engine, фазовые ресурсы и cleanup подтверждены.
