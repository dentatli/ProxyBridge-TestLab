# Preview.62: свежие policy-события и надёжное чтение результатов

Исправления после [WFP H2 аудита](PB_SUT_WFP_H2_61_AUDIT_2026-10-27.md).

- Перед серией DIRECT/BLOCK команда POLICY_BEGIN вызывает существующий Core ClearConnectionLogs. Это очищает кеш дедупликации callbacks WFP, не правила, не собственные накопительные счётчики и не активные соединения. Требования свежего события, правильной доставки, здорового получателя и приоритета DIRECT над fallback BLOCK сохранены.
- Native FINISHED/FAILED остаются до явного worker-ack. Повторные чтения возвращают тот же результат; ACK идемпотентен (ограниченный кеш 64 подтверждений, максимум 8 неполученных заданий). При ошибке задачи передаётся подписанный безопасный код/тип/HResult/socket errno, без stack/arbitrary message.
- Python повторяет только worker-result/worker-ack при OSError/EOFError, максимум три попытки в прежнем deadline. worker-start никогда не повторяется. Неисправная подпись/структура не дают повторной отправки. После неуспеха остаются первая/последняя ошибка, операция, последний статус и признак подтверждённого запуска. Полученный, но неподтверждённый результат хранится отдельно и не становится PASS.
- Endurance сохраняет первичную worker-ошибку до последующих проблем изоляции/очистки. Неизвестный результат по-прежнему останавливает попытку.

## Проверка

MSVC /W4 /WX Core host и C# Release publish успешны; два policy evidence guard теста успешны, включая требование POLICY_BEGIN перед SNAP. Существующий native contract gate дополнен тремя необходимыми проверками: потеря FINISHED+ACK ответа с единственным запуском, подписанная ошибка задачи, bounded retry/сохранение errno/отказ без retry при неверной подписи. Новые три контракта PASS отдельно (ack62.log). Первый полный gate дошёл до новых тестов после прежних35, но новая проверка сравнивала изменяемый dict по ссылке: исправлено копирование test snapshot. Повтор полного gate остановлен прежним churn transport FAIL на VM (contracts62-final.log); в системе уже загружен чужой WinDivert64.sys. Ни это отклонение, ни исходный H2 не объявлены PASS. Короткая функциональная приёмка на свободном PB-SUT фиксируется в checkpoint после завершения.

На VM проверка включения WFP штатно отказала до изменения устройства: в системе уже загружен WinDivert64.sys. Чужой драйвер не выгружался, gate не обходился. Повторять короткую WFP-приёмку на свободном PB-SUT после обновления.

Историческую причину исчезновения persistent TCP результата примерно через час эти изменения задним числом не доказывают. Они устраняют потерю результата при кратком разрыве чтения и сохраняют причины при повторном отказе. Новый H2 запускает пользователь; автоматически длительный прогон не запускать. Продуктовые DLL/SYS не меняются.
